## The one file

Everything visual comes from `packages/rabtx/src/styles/theme.css`. It is laid out like a shadcn
theme:

- `:root` holds the light values and `.dark` the dark ones, as `background` / `foreground` pairs:
  `--primary` is a surface, `--primary-foreground` is the text and icons on it.
- `@theme inline` maps every token into Tailwind, so `bg-primary`, `text-muted-foreground`,
  `border-input` and `rounded-lg` work and stay live when a variable changes.
- `--radius` is the one corner radius. Tailwind's `rounded-sm` to `rounded-4xl` and the Rabtx radius
  tiers are derived from it.

Components read nothing else: no colors, radii or shadows are written into a component. Change a
value in this file and the web app, these docs and every component installed from the registry
follow.

## Customising

**The whole theme.** Edit `theme.css`. To swap in a theme from the
[shadcn themes page](https://ui.shadcn.com/themes) or tweakcn, paste its `:root` and `.dark`
blocks over the shadcn tokens; the Rabtx tokens below keep working.

**Part of a page.** Set tokens on any ancestor. Everything inside follows.

```tsx
<section className="[--primary:var(--success)] [--radius:0.25rem]">
  <Button>Approve</Button>
</section>
```

**One component.** Pass Tailwind classes. Components put their own styles in the `components`
layer, so your utilities win: `<Button className="rounded-md">`.

**A subtree only.** Add the class `rabtx` to apply the theme to one element and its children; it
follows a `.dark` ancestor, or pin it with `rabtx light` or `rabtx dark`. The web app and this site
use that to embed Rabtx next to their own themes.

**In a shadcn project.** Components from the registry read your existing shadcn theme. Add the Rabtx
theme on top with `npx shadcn@latest add @rabtx/theme`; without it, the Rabtx-only tokens (status
tones, field depth and the rest) are derived from your shadcn colors.

### Why there are no per-component variables

Earlier versions had a layer of component variables (`--rx-btn-primary-bg`, `--rx-select-panel`
and so on) on top of the tokens. They are gone: every component reads the semantic tokens directly,
which is what makes one file restyle everything and lets a shadcn theme drop straight in. To change
one component, set a semantic token on it or an ancestor, or pass classes. Each component page lists
the tokens it reads under **Theming**.

## Modes

Set on any ancestor, never as a component prop.

| Mode | Values | Effect |
| --- | --- | --- |
| `class="dark"` | present or not | The `.dark` values |
| `data-depth` | `floating` (default), `flat` | `flat` drops the raised edges, sheens and shadows |
| `data-radius` | `sharp`, default, `round` | Overrides the radius tiers |
| `data-motion` | `on` (default), `off` | `off` stops every transition; reduced motion in the OS does too |
