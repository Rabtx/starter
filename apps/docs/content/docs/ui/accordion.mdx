## Installation

<Installation name="accordion" />

The accordion is built on [Collapsible](/docs/ui/collapsible), which the command installs with it.

## Usage

Installed from the registry, import from `@/components/ui/accordion`; inside this monorepo, from
`@rabtx/ui/accordion`. The API is shadcn's.

```tsx
import { Accordion, AccordionContent, AccordionItem, AccordionTrigger } from "@rabtx/ui/accordion";

export function Faq() {
  return (
    <Accordion type="single" collapsible defaultValue="refunds">
      <AccordionItem value="plans">
        <AccordionTrigger>Can I change plans later?</AccordionTrigger>
        <AccordionContent>Yes. Upgrades apply at once and are prorated.</AccordionContent>
      </AccordionItem>
      <AccordionItem value="refunds">
        <AccordionTrigger>Do you offer refunds?</AccordionTrigger>
        <AccordionContent>Within 14 days of any charge, no questions asked.</AccordionContent>
      </AccordionItem>
    </Accordion>
  );
}
```

Every item is a `<details>` and its trigger the `<summary>`, so the trigger must be the item's first
child and everything after it is what folds. A single accordion gives its items one `name`, so the
browser itself keeps one open, even before the page hydrates.

## Variants

`separated` (the default) is one joined stack: the open item lifts out with a gap on either side
and the rows around it round the corners that face it. `cards` makes every item its own card, and
`flush` is a plain list divided by lines.

## Collapsible and disabled

A single accordion keeps its open item open unless it is `collapsible` (as in Radix and the
WAI-ARIA pattern); that trigger reports `aria-disabled` while it cannot close. A `disabled` item is
dimmed, leaves the Tab order and is skipped by the arrow keys.

## Controlled

`value` and `onValueChange` control it. `""` means none open (single).

<ComponentPreview name="accordion/controlled" />

## Find in page

Closed content is still in the page. Find in page (Ctrl+F), a link to text inside it
(`#:~:text=`) or a link to an `id` inside it opens the item, because the browser opens a `<details>`
itself (Chromium; other browsers keep it closed). The accordion takes that as a request like a
press: a single accordion moves to the item, and a controlled one sees `onValueChange`. Native
`<details>` does this without `hidden="until-found"`.

## Modes

Corners follow `data-radius` (the box tier). `data-depth="flat"` draws one plain border and drops
the ring and sheen. `data-motion="off"` opens and closes at once.

## API

`Accordion` takes everything a `div` takes, plus:

<TypeTable
  type={{
    type: { type: '"single" | "multiple"', default: '"single"' },
    value: { type: "string | string[]", description: "The open item (single, \"\" for none) or items (multiple). Controlled." },
    defaultValue: { type: "string | string[]", description: "Open first (uncontrolled)." },
    onValueChange: { type: "(value: string | string[]) => void", description: "After every change, in the shape of value." },
    collapsible: { type: "boolean", default: "false", description: "Single only: whether the open item can close, leaving none open." },
    variant: { type: '"separated" | "cards" | "flush"', default: '"separated"' },
  }}
/>

`AccordionItem` takes everything a `details` takes except `open` and `name`, plus a required
`value` and `disabled`. `AccordionTrigger` takes everything a `summary` takes, plus `icon` (a
decorative icon before the title). `AccordionContent` takes everything a `div` takes; it is a
`region` named by its trigger.

Outside React, the class names are exported from `@rabtx/ui/accordion/styles`
(`accordionClass()`, `accordionParts`). It works with no script:

```html
<div class="rx-accordion rx-accordion-separated">
  <details class="rx-collapsible rx-accordion-item" name="faq" open>
    <summary class="rx-collapsible-trigger rx-accordion-trigger">
      <span class="rx-accordion-title">Do you offer refunds?</span>
      <span class="rx-collapsible-chevron" aria-hidden="true"></span>
    </summary>
    <div class="rx-collapsible-content rx-accordion-content">Within 14 days of any charge.</div>
  </details>
</div>
```

## Theming

The accordion reads only the [theme tokens](/docs/ui/theming).

| Part | Tokens |
| --- | --- |
| Surface (separated, cards) | fill `--card` (3% `--foreground` on hover), the surface edges, ring, sheen and shade; `--border` in Flat |
| Flush | divider `--border` |
| Title, content | `--card-foreground`, `--muted-foreground` |
| Focus | `--ring` |
| Corners | `--radius-box` (sharp 4, default 12, round 20) |
| Motion | `--spring-expand` (open, gaps, corners), `--spring-glide` (close), `--spring-swap` (chevron), `--motion-ease` |

## How the motion works

| Effect | CSS |
| --- | --- |
| Height | `interpolate-size: allow-keywords` lets `::details-content` transition `block-size` from 0 to `auto`; `content-visibility` transitions with `allow-discrete`, so closing stays visible to the end |
| Bounce | opening rides the `expand` spring (117 / 14.7 / 1, about 5% overshoot, settles in about 890ms), so the height lands a little past its size and settles; closing glides (360 / 32 / 0.6, no overshoot) |
| Lift (separated) | margins and corners picked by `[open] + *` and `:has(+ [open])`, transitioned on the same spring while anything is open |
| Content | rises 4px out of a 4px blur (`@starting-style` covers the first frame), 50ms after the height starts; closing fades in 120ms |
| Chevron | `rotate: 180deg` on the swap spring |
| Fallback | without `interpolate-size` (Safari, Firefox today) `::details-content` is a one-row grid going from `0fr` to `1fr`; without `::details-content` the content appears at once and still fades |

## Accessibility

- Each trigger is a `<summary>`: a button with its expanded state, toggled by Enter and Space,
  reported by the browser. Each panel is a `region` named by its trigger.
- Up and down arrows move between triggers and wrap; Home and End jump to the ends; disabled items
  are skipped. Tab moves through triggers and the content of open items.
- Closed content is out of the accessibility tree and the Tab order (the browser hides it).
- Keyboard focus shows a 2px ring on the trigger.
- With reduced motion nothing grows, turns or blurs; content fades in 100ms. With
  `data-motion="off"` every state changes at once.
