`packages/rabtx` (`@rabtx/ui`) is the component library for the apps. Components are native elements
with semantic HTML, styled with Tailwind and modern CSS. Every animation is CSS (transitions,
`@keyframes`, `@starting-style` and springs solved into `linear()` easings); JavaScript only sets
state or CSS variables. Icons are HugeIcons, passed in as children or props.

## Installation

Add the workspace package to an app, then import its styles once after Tailwind. The styles scan
the component classes themselves, so there is no `@source` line to add.

```bash
bun add @rabtx/ui@workspace:*
```

```css
@import "tailwindcss";
@import "@rabtx/ui/styles.css";
```

Next.js apps also list it in `transpilePackages`, because the package ships TypeScript source.

## Theming

One file themes everything: `packages/rabtx/src/styles/theme.css`. It uses shadcn/ui's token names
(`--background`, `--primary`, `--muted-foreground`, `--border`, `--ring`, `--radius` and the rest)
on `:root` and `.dark`, maps them into Tailwind with `@theme inline`, and adds a few Rabtx tokens
for status tones, depth, radius tiers, shadows and springs. Components read nothing else, so
changing a value there restyles the web app, these docs and every component installed from the
registry. See [Theming](/docs/ui/theming) for every token.

## Modes

Components never take a prop for theme, radius or motion. Set a class or an attribute on any
ancestor and everything inside follows.

- `class="dark"`: dark colors. `class="rabtx"` applies the theme to one subtree only, which is how
  this site and the web app embed it next to their own themes.
- `data-depth`: `flat` or `floating`, for fields and cards
- `data-radius`: `sharp`, `default` or `round`
- `data-motion`: `on` or `off`. Reduced motion in the OS turns motion down as well.
