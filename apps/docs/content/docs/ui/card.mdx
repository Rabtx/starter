## Usage

Installed from the registry, import from `@/components/ui/card`; inside this monorepo, from
`@rabtx/ui/card`.

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@rabtx/ui/card";

export function Invite() {
  return (
    <Card>
      <CardHeader>
        <CardTitle as="h3">Invite your team</CardTitle>
        <CardDescription>Teammates can view and edit every project.</CardDescription>
        <CardAction>
          <Button variant="ghost" size="sm">Later</Button>
        </CardAction>
      </CardHeader>
      <CardContent>…</CardContent>
      <CardFooter>
        <Button size="sm">Send invites</Button>
      </CardFooter>
    </Card>
  );
}
```

The parts are shadcn's, with the same `data-slot` names, so a shadcn card drops in. Each part pads
itself on the inline axis, so any of them can be left out. `CardAction` pins to the top right of
the header; the header is a container, and under 15rem wide the action drops below the title.

## Sizes

`size` is `sm`, `default` or `lg`: 12, 16 or 20px of padding including the 1px edge (Figma's
Kanban, Option and Stat cards).

<ComponentPreview name="card/sizes" />

## Media

An `img`, `video`, `picture` or anything with `data-slot="card-media"` placed directly in the card
runs edge to edge and takes the card's corners when it is first or last.

<ComponentPreview name="card/media" />

## Link card

A card never takes focus itself. Put `cardParts.target` on the one link or button that owns it:
the target's hit area stretches over the card, and the card answers hover (a stronger edge),
press (a spring down to 0.985) and keyboard focus (the ring is drawn on the card), all through
`:has()`. Other links and buttons in the card stay on top and keep working.

<ComponentPreview name="card/link" />

```tsx
<Card as="article">
  <CardHeader>
    <CardTitle as="h3">
      <a href="/repos/ui" className={cardParts.target}>rabtx/ui</a>
    </CardTitle>
  </CardHeader>
</Card>
```

## Selectable

Make the target a `label` around a radio or checkbox. A click anywhere on the card picks it, and
the checked input marks the card selected with a `--primary` edge. A disabled input dims the card
and turns off its hover and press. `data-selected`, `aria-pressed="true"` or `aria-current` on the
target select it too.

<ComponentPreview name="card/selectable" />

## Tilt

`TiltCard` leans toward a mouse or pen in 3D, up to `max` degrees at a corner (default 10), with a
soft glare under the pointer, and springs back flat when the pointer leaves. Touch, reduced motion
and `data-motion="off"` keep it flat.

<ComponentPreview name="card/tilt" />

## Spotlight

`SpotlightCard` carries a soft light after the pointer and lights the part of the edge nearest to
it. The light is `--primary`, so one token recolors a card. When a link or button inside has
keyboard focus, the light rests along the top.

<ComponentPreview name="card/spotlight" />

## Expandable

`ExpandableCard` is a `<details>` element: the summary row is the toggle, so the browser provides
the button role, the expanded state, Enter and Space, and opening for find-in-page. A shared
`name` keeps one card of a group open, natively. The content grows to its height on the panel
spring and the chevron turns over.

<ComponentPreview name="card/expandable" />

## Stack

`CardStack` piles its cards behind the first, each a little smaller, and spreads them into a list.
The toggle is a real button with `aria-expanded`; while collapsed its hit area covers the pile, so
a click or tap anywhere opens it. A mouse over the pile fans the peeks a little further. Cards of
similar height stack best.

<ComponentPreview name="card/stack" />

## Modes

Depth and radius follow `data-depth` and `data-radius` on any ancestor. Flat is one 1px border;
Floating is the raised surface (a light top edge, a dark bottom edge and a hairline ring, no cast
shadow). Radius uses the box tier: 12px, 4px in Sharp and 20px in Round, never a capsule.

## API

Every part takes everything its native element takes. `Card` adds:

<TypeTable
  type={{
    size: { type: '"sm" | "default" | "lg"', default: '"default"', description: "12, 16 or 20px padding." },
    as: { type: '"div" | "article" | "section" | "aside" | "li"', default: '"div"' },
  }}
/>

`CardTitle` takes `as` (`div`, `h2` to `h6`); `CardDescription` is a `p` (or `div`); `CardHeader`
and `CardFooter` can render `header` and `footer`, which is right inside an `article` or
`section` card. `TiltCard` and `SpotlightCard` take the `Card` props, and `TiltCard` adds:

<TypeTable
  type={{
    max: { type: "number", default: "10", description: "Degrees of turn at a corner." },
    glare: { type: "boolean", default: "true", description: "The highlight under the pointer." },
  }}
/>

`ExpandableCard` takes everything a `<details>` takes, plus:

<TypeTable
  type={{
    title: { type: "ReactNode", description: "The summary heading and the toggle's accessible name." },
    description: { type: "ReactNode", description: "A line under the title, always visible." },
    size: { type: '"sm" | "default" | "lg"', default: '"default"' },
    open: { type: "boolean", description: "Controlled, with onOpenChange." },
    defaultOpen: { type: "boolean", default: "false" },
    onOpenChange: { type: "(open: boolean) => void" },
    name: { type: "string", description: "Cards sharing a name open one at a time." },
  }}
/>

`CardStack` takes everything a `<section>` takes, plus:

<TypeTable
  type={{
    noun: { type: "string", default: '"cards"', description: 'For the toggle: "Show all 4 notifications".' },
    peek: { type: "number", default: "2", description: "Cards peeking out behind the first." },
    expanded: { type: "boolean", description: "Controlled, with onExpandedChange." },
    defaultExpanded: { type: "boolean", default: "false" },
    onExpandedChange: { type: "(expanded: boolean) => void" },
    showLabel: { type: "string", description: 'Replaces "Show all N {noun}".' },
    hideLabel: { type: "string", default: '"Show less"' },
  }}
/>

Outside React, `cardClass()` and `cardParts` from `@rabtx/ui/card/styles` give the class names:

```html
<article class="rx-surface rx-card">
  <div class="rx-card-header">
    <h3 class="rx-card-title"><a class="rx-card-target" href="/a">Title</a></h3>
    <p class="rx-card-description">Description</p>
  </div>
</article>
```

## Theming

The Card reads only the [theme tokens](/docs/ui/theming).

| Part | Tokens |
| --- | --- |
| Surface | fill `--card`, text `--card-foreground`, Flat edge `--border` |
| Floating depth | `--surface-ring`, `--surface-edge-top`, `--surface-edge-bottom`, `--surface-sheen`, `--surface-shade` |
| Description | `--muted-foreground` |
| Hover (link, selectable, expandable) | edge `--input`, ring mixed toward `--card-foreground` |
| Selected | `--primary` |
| Focus | `--ring` |
| Tilt glare | `--card-foreground` at 10% |
| Spotlight | `--primary` |
| Corners | `--radius-box` |
| Motion | `--spring-press`, `--spring-magnetic`, `--spring-panel`, `--spring-swap`, `--motion-ease` |

## How the motion works

| Effect | CSS |
| --- | --- |
| Interactive card | `.rx-card:has(.rx-card-target)` gets hover inside `@media (hover: hover) and (pointer: fine)`, `scale: 0.985` while the target is `:active` on the press spring, and the focus ring when the target is `:focus-visible` |
| Selected | `:has(.rx-card-target :checked)` swaps the edge variables to `--primary` |
| Tilt | the pointer writes `--_tilt-x` and `--_tilt-y`; `transform: perspective() rotateX() rotateY()` transitions on the magnetic spring; the glare is a radial gradient at `--_px` / `--_py` under the content |
| Spotlight | two pseudo-elements at `--_px` / `--_py`: a wide radial light inside, and a narrower one on a 1px padded layer whose content box is masked out (`mask-composite: exclude`), so only the edge lights |
| Expandable | `interpolate-size: allow-keywords` lets `::details-content` transition `block-size` from 0 to `auto` on the panel spring, with `content-visibility` kept until it ends (`allow-discrete`) |
| Stack | each item is a one-row grid with its card aligned to the bottom (`align-items: unsafe end`); collapsed an item is 10px tall so its card overflows upward behind the one before, open it grows to `auto` with `interpolate-size`, and the cards scale back from `1 - i × 0.05` |
| Chevrons | `rotate` on the swap spring |

JavaScript only writes the pointer position and the expanded state. The springs are fixed
`linear()` curves: a tilt that is interrupted restarts from where it is.

## Browser support

- **Chromium 131+:** everything, including the expanding details and stack heights.
- **Safari and Firefox:** cards, link and selectable cards, tilt and spotlight work; without
  `interpolate-size` and `::details-content` the expandable card and the stack change height at
  once instead of animating.

## Accessibility

- A card adds no role and no tab stop. Use `as="article"` or a labelled `section` where the card
  is a unit of its own, and `CardTitle as` for the right heading level.
- A clickable card is a real link, button or label inside it, so its name, role and keyboard come
  from that element. Name a link by its text, not "Read more".
- `ExpandableCard` is native `details` and `summary`. The stack's toggle is a button with
  `aria-expanded` and `aria-controls`, and the cards behind are `inert` while collapsed.
- Tilt and spotlight are decoration: they ignore touch, and reduced motion or `data-motion="off"`
  keeps the card flat and drops every fade and height animation.
