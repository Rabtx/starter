## Usage

Installed from the registry, import from `@/components/ui/slider`; inside this monorepo, from
`@rabtx/ui/slider`.

```tsx
import { Slider } from "@rabtx/ui/slider";

export function PriceFilter() {
  const [price, setPrice] = useState([200, 800]);
  return (
    <Slider aria-label="Price" value={price} onValueChange={setPrice} max={1000} step={10} />
  );
}
```

Values are arrays, as in shadcn: one number is a slider, two (or more) a range. Every thumb is an
`<input type="range">`, so the browser provides the slider role, the value, minimum and maximum
for screen readers, arrow keys, Page Up and Down, Home and End, and the form value. Name it with a
`Field` or an `aria-label`.

## Sizes

`sm` (4px track, 16px thumb), `md` (6 and 20, the default) and `lg` (8 and 24). The input is
always at least 24px tall, so the small size keeps a usable target.

<ComponentPreview name="slider/sizes" />

## Value bubble

`showValue` puts the value over the thumb while it is hovered, focused or dragged; `"always"`
keeps it out. `formatValue` formats the bubble and the value read to screen readers
(`aria-valuetext`). The bubble is decorative (`aria-hidden`): the input already announces the value.

<ComponentPreview name="slider/bubble" />

## Marks

`marks` draws ticks under the track (never under the thumb): `true` for every step (up to 100),
or a list of values, each with an optional label. Ticks inside the filled part take the fill color.
The values also fill a `<datalist>` linked with the inputs' `list` attribute.

<ComponentPreview name="slider/marks" />

## Ruler

`variant="ruler"` swaps the round thumb for a needle over a tick scale, with a large readout above.
The scale draws a tick every step (or every few steps, so there are at most 100); labelled `marks`
add taller ticks underneath.

<ComponentPreview name="slider/ruler" />

## Vertical

`orientation="vertical"` stands the slider up with the native vertical writing mode, minimum at
the bottom; Arrow Up raises it. Give it a height (12rem by default). Bubbles open to the side.

<ComponentPreview name="slider/vertical" />

## States

Disabled is dimmed to 50%, skipped by Tab and ignores the pointer. Inside a `Field` the label
names the slider, the hint describes it, and `error` turns the rail edge and the thumb
`--destructive` and links the message.

<ComponentPreview name="slider/states" />

## Range and controlled

Two values make a range: one input per thumb, overlaid on a shared track. Each thumb is clamped
between its neighbours, `minStepsBetweenThumbs` apart, so they can meet but never cross. Pressing
the bare track moves the nearest thumb there and follows the pointer. `onValueChange` fires on
every move; `onValueCommit` fires when a drag or a key press ends (the native `change` event).

<ComponentPreview name="slider/controlled" />

## Forms

A slider submits under its `name`; a range submits one entry per thumb, read with
`formData.getAll(name)`.

## Right to left

The native range runs from the inline start, and the fill, bubbles and marks follow it.

## Modes

Corners follow `--radius-button` (round thumbs in Default and Round, squared in Sharp). Flat drops
the recess on the rail and the ring on the thumb. Motion off keeps every state but moves nothing.

## API

`Slider` takes everything a `<div>` takes (on the root), plus:

<TypeTable
  type={{
    value: { type: "number[]", description: "Controlled values, one per thumb." },
    defaultValue: { type: "number[]", default: "[min]", description: "Uncontrolled initial values." },
    onValueChange: { type: "(value: number[]) => void", description: "Every move." },
    onValueCommit: { type: "(value: number[]) => void", description: "When a drag or a key press ends." },
    min: { type: "number", default: "0" },
    max: { type: "number", default: "100" },
    step: { type: "number", default: "1" },
    minStepsBetweenThumbs: { type: "number", default: "0", description: "Steps kept between neighbouring thumbs." },
    orientation: { type: '"horizontal" | "vertical"', default: '"horizontal"' },
    size: { type: '"sm" | "md" | "lg"', default: '"md"' },
    variant: { type: '"default" | "ruler"', default: '"default"' },
    showValue: { type: 'boolean | "always"', default: "false", description: "A value bubble over each thumb." },
    formatValue: { type: "(value: number) => string", description: "Formats the bubble, the readout, the datalist and aria-valuetext." },
    marks: { type: "boolean | (number | { value: number; label?: ReactNode })[]", description: "Ticks under the track." },
    thumbLabels: { type: "string[]", default: '["Minimum", "Maximum"]', description: "Each thumb's name in a range." },
    name: { type: "string", description: "Form field name; a range submits one entry per thumb." },
    form: { type: "string" },
    disabled: { type: "boolean" },
  }}
/>

Outside React, the class names are exported from `@rabtx/ui/slider/styles`. The fill reads
`--_lo` and `--_hi` (numbers from 0 to 1) from the root:

```html
<div class="rx-slider rx-slider-md" data-orientation="horizontal" style="--_lo: 0; --_hi: 0.4">
  <div class="rx-slider-control">
    <div class="rx-slider-layer">
      <input type="range" class="rx-slider-input" value="40" aria-label="Volume" />
    </div>
  </div>
</div>
```

## Theming

The Slider reads only the [theme tokens](/docs/ui/theming).

| Part | Tokens |
| --- | --- |
| Rail and fill | rail `--muted-foreground` (22% over `--background`), fill `--primary` |
| Thumb | `--background` with a `--primary` edge; halo `--primary` at 18% |
| Bubble | `--foreground` with `--background` text |
| Marks | `--muted-foreground`, inside the fill `--primary` |
| Depth (Floating) | rail `--field-edge-top`, `--field-edge-bottom`; thumb `--surface-ring`, `--surface-sheen`, `--surface-shade` |
| Focus and error | `--ring`, `--destructive` |
| Corners and motion | `--radius-button`, `--radius-item` (bubble), `--spring-press`, `--spring-swap`, `--motion-ease` |

## How it works

| Effect | CSS |
| --- | --- |
| Fill | the component writes `--_lo` and `--_hi`; the rail is one `linear-gradient` with stops at `thumb / 2 + (100% - thumb) * p`, the path the native thumb's centre travels, on `::-webkit-slider-runnable-track` and `::-moz-range-track` (a range paints it once, on a shared track under the inputs) |
| Range | one input per thumb, stacked; the inputs ignore the pointer and their thumbs take it back (`pointer-events: auto`), so each thumb drags natively; the last-used thumb sits on top, and thumbs meeting at the maximum put the lower one on top |
| Press | `:active` grows the thumb to 1.2 with a 5px halo on the `press` spring (500 / 30 / 0.6); hover shows a 4px halo |
| Bubble | positioned at `--_p` with the same formula, so it stays on the thumb; out on `:hover`, `:focus-visible` and `:active` with scale 0.5 to 1 and 6px up on the `swap` spring, away in 120ms |
| Ruler | the scale is the fill gradient masked by a `repeating-linear-gradient` of 1px ticks, intersected with a lower-half mask |
| Vertical | `writing-mode: vertical-lr; direction: rtl` on the input, so the browser lays the range out bottom to top |

JavaScript only keeps the values, clamps the thumbs and handles a press on a range's bare track.
Thumbs cannot be anchors for CSS anchor positioning (they are pseudo-elements), which is why the
bubble reads a variable instead.

Not built, because they need JavaScript animation: a bubble that leans with drag velocity, a ruler
scale that scrolls under a fixed needle with momentum, bars that rise into a travelling crest, and
a thumb that parts around inline labels. The thumb itself jumps with the native input rather than
gliding on a spring, so the value under the pointer is always exact.

## Browser support

- **Everywhere:** `appearance: none` on ranges, the WebKit and Firefox thumb and track
  pseudo-elements, `color-mix()`, nesting, `:has()`, `mask-composite` and `linear()` easings:
  Chrome 120+, Safari 17.2+ and Firefox 128+ (from compatibility data; tested in Chrome).
- **Vertical:** `writing-mode` on a range needs Chrome 124+, Safari 17.4+ or Firefox 120+.

## Accessibility

- Every thumb is a native slider: role, value, minimum, maximum and orientation come from the
  input, and `formatValue` adds `aria-valuetext`.
- A range's thumbs are named by the label and their own name ("Price Minimum", "Price Maximum"),
  with `aria-labelledby` pointing at the Field label and the thumb.
- Arrow keys step, Page Up and Down move by a tenth, Home and End go to the ends; a range thumb
  stops at its neighbour.
- Focus shows a 2px `--ring` outline around the thumb. Value is shown by position and the fill,
  never motion alone; reduced motion only fades the bubble and `data-motion="off"` moves nothing.
